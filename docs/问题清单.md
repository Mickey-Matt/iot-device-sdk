# 问题清单

已经发现、但还没动手改的问题

分三类：

- **确认的缺陷** —— 会出错，只是还没触发
- **已知的取舍** —— 故意的，写清楚为什么
- **工程缺口** —— 测试、工具、验证范围

每条记：现象 → 影响 → 怎么发现的 → 建议改法 → 涉及文件

## 一、确认的缺陷

### 1. 手工拼 JSON 不转义，device_id 里出现引号就会拼出非法报文

`MqttSink::Publish()` 用 `snprintf` 手工拼：

```cpp
R"({"device_id":"%s","timestamp_ms":%lld,...)"
```

`config_.device_id` 是使用者配的字符串，里面只要有 `"` 或 `\`，拼出来就不是合法 JSON

同一个问题在 `MockSource::BuildFrame()` 里也有

**为什么一直没暴露**：本项目里 device_id 固定是 `fish-tank-01`，不含特殊字符

**改法二选一**：拼之前对字符串做 JSON 转义（项目里已有 `json::Dump`，可以借它转义单段字符串）；或者直接用 `json::Dump` 构造整条报文，放弃"手工拼接演示省内存"这个教学点

涉及 `src/mqtt_sink.cpp` 的 `Publish()`、`src/mock_source.cpp` 的 `BuildFrame()`

### 2. snprintf 截断了不会报错，会静默发出半截 JSON

`char buf[256]` 是固定大小，超了 `snprintf` 就截断，函数照样返回成功

结果是：报文发出去了半截，云端解析失败，而这边日志写着"上报成功" —— 又是一次"日志和报文不一致"

`snprintf` 的返回值是**本该写入的长度**（不含结尾 `\0`），拿它和 `sizeof(buf)` 比一下就能发现

涉及 `src/mqtt_sink.cpp` 的 `Publish()`、`src/mock_source.cpp` 的 `BuildFrame()`

### 3. device_id 有两个来源，不一致时没人发现

- `MqttSink::Publish()` 拼**主题**和**载荷**都用 `config_.device_id`
- `DeviceMessage.device_id` 是 `ParseFrame()` 从数据源报文里解出来的

两者不一致时（比如模拟器报的是 A、配置里写的是 B），会发出"主题说是 B、数据其实来自 A"的报文，代码不做任何检查

**顺带**：`DeviceClient` 自己也没有 device_id 概念，它从报文里拿。将来要做"事件触发的主动上报"（比如温度告警立即上报，不等下个采集周期），device_id 没有来源

涉及 `src/mqtt_sink.cpp` 的 `Publish()`、`src/device_client.cpp` 的 `ParseFrame()`

### 4. ParseFrame 不解析 uptime_ms 和 seq

上行报文里有这两个字段（踩坑记录第 14 条加的），但 `ParseFrame()` 不读它们

结果是**自己发出去的报文，自己解析不回来这两项**。做回环测试（发出去再收回来比对）时会丢字段

涉及 `src/device_client.cpp` 的 `ParseFrame()`

### 5. 进程被强杀时，日志缓冲区里的内容丢失

`Logger` 只有正常调 `Close()` 才落盘。用 `timeout` 掐掉或强杀进程时，最后一段日志不在文件里 —— **而最后那段往往正是出问题那段**

实测：`timeout 4 ./device_sim.exe 500` 之后，日志文件内容不完整

改法：定期 flush，或者在信号处理里 flush（`device_sim` / `mqtt_demo` 都已经有 SIGINT 处理，在那里加一次即可）

涉及 `src/logger.cpp`

## 二、已知的取舍（故意的，不是漏做）

### 6. 上报失败直接丢数据，不重发

`MqttSink::PublishRaw()` 在未连接时直接返回 false，不排队

理由：遥测数据"过期就没价值"，断网 30 秒后补发 30 秒前的温度没有意义

如果业务要求不丢，两条路：`clean_session=false` 让 broker 暂存；或者自己做本地持久化队列

### 7. 手工拼 JSON 而不是用 json::Dump

教学考虑（演示设备侧怎么产生报文，真实嵌入式也是这么一位一位拼的）

代价就是上面第 1、2 条

### 8. MockSource 的坏帧是写死的

每 7 帧注入一次，坏帧内容硬编码。`InjectCorruptedFrame()` 这个开关**没有任何地方调用**（本来是给单测准备的）

## 三、工程缺口

### 9. 单元测试没覆盖重构后的主链路

44 个测试全在 `tests/test_json.cpp` 里，覆盖的是 JSON 解析和 `DeviceClient::ParseFrame()`

**没覆盖**：`DeviceClient::PollOnce()` 的五个步骤、`MqttSink::Publish()` 的 JSON 拼装、`LogSink`

这次重构能安全落地靠的是**手工端到端验证**（起 broker + `mosquitto_sub` 抓包对照），不是单测

补一个"假 sink"（记录收到了什么，不发出去）就能把 `PollOnce` 整条链路测起来 —— `ITelemetrySink` 是接口，写个测试用的实现正是它的用处

### 10. 端到端验证还是手工的

"起 broker → 跑程序 → `mosquitto_sub` 抓包 → 和日志对照"这套流程每次手敲

可以做成一个脚本（记下 broker 端口、订阅、等待、比对）

### 11. 只测了本机 localhost

跨网络、TLS、broker 鉴权都没测

### 12. 真实串口时序没验证过

半包、粘包、超长帧用模拟器和单测覆盖了，真实硬件的时序没条件验证

### 13. 多设备并发没压测

`MqttConfig::client_id` 已经支持自动生成唯一 ID，但没同时跑过多个实例
