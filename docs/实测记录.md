## 退出统计

```
19:18:16.674 [INFO ] MQTT 已断开：MqttSource(localhost:1883)（统计：连接成功 2 次，收到 2 条，发布成功 358 条，发布失败 19 条）
19:18:16.674 [INFO ] DeviceClient 已停止。统计：收到 0 帧，成功 0 帧，解析失败 0 帧，数据源错误 0 次
```

`DeviceClient` 收到 0 帧，是因为当时数据源就是 MQTT 本身
MQTT 不产生传感器读数，它的"待投递队列"默认不接收任何东西（`queue_downlink` 默认 false），
所以那个"数据源"实际上一直空转

这个结论直接导致了后续的重构：**MQTT 不是数据源，是出口**

## 主循环时序（已查清）

上报间隔实测 3.12 秒，设计值 2 秒（`mqtt_demo.cpp` 每 100 轮 `sleep_for(20ms)`）
每轮实测 31.25ms，其中循环体只占约 0.002ms
把 `sleep_for` 改成 `0ms` 实测 1000 轮只要 2ms，证明循环体本身几乎不花时间
多出来的 11.25ms 是 Windows 调度节拍（默认约 15.6ms）把 `sleep_for(20ms)` 向上取整到两个节拍所致，不是 `PollOnce()` 的锁竞争、也不是日志输出

> 这段是重构【之前】的记录，那时上报节奏由主循环的轮数决定
> 重构后节奏由 `MockSource` 的间隔参数决定（构造时传 3000 就是 3 秒一次），
> 主循环的 20ms 只影响"多快响应一条下行命令"
